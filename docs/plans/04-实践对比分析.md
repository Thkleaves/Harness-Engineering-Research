# 04 — 实践对比分析

> **优先级**: ⭐⭐⭐⭐ 高（选型决策参考）  
> **目的**: 基于实操体验，从多个维度对比评估各工具的优劣势  
> **方法**: 官方文档 + 实操 + 社区评价 + 模拟场景测试

---

## 4.1 对比方法论

本对比基于以下五个典型场景对各工具进行评分（满分 5⭐）：

```
1. 上手体验: 从零到第一次成功使用的耗时和难度
2. 日常开发: 日常编码任务中的体验和效率
3. 质量控制: 发现和阻止问题的能力
4. 团队协作: 多人环境下的工作一致性
5. 成本效益: 引入 Harness 带来的 Token/时间开销 vs 收益
```

## 4.3 各维度详细对比

### 4.3.1 上手体验

| 维度 | Superpowers | agent-harness-kit | HarnessForge |
|------|-------------|-------------------|-------------|
| 安装步骤 | 2 步（plugin marketplace → install） | 3 步（npm install → init → config） | 1 步（pip install → init） |
| 首次成功 | ~10 min（含理解流程） | ~30 min（含配置调优） | < 1 min |
| 文档质量 | ⭐⭐⭐⭐⭐ 完善，中英文丰富 | ⭐⭐⭐⭐ 完整但全英文 | ⭐⭐⭐ 较少但够用 |
| 社区帮助 | 丰富（30K stars，多个中文教程） | 中等（~500 stars） | 较少（~200 stars） |

**结论**: HarnessForge 上手最快，Superpowers 次之（但需要时间理解流程），agent-harness-kit 需要最多的配置投入。

### 4.3.2 日常开发体验

| 维度 | Superpowers | agent-harness-kit | HarnessForge |
|------|-------------|-------------------|-------------|
| 小功能 (<1h) | 体验 ⭐⭐⭐（有流程开销） | 体验 ⭐⭐⭐⭐ | 体验 ⭐⭐（仅配置，无流程） |
| 中功能 (2-4h) | 体验 ⭐⭐⭐⭐⭐ | 体验 ⭐⭐⭐⭐ | — |
| 大功能 (>4h) | 体验 ⭐⭐⭐⭐⭐ | 体验 ⭐⭐⭐⭐⭐ | — |
| 调试体验 | ✅ 系统性调试流程 | ✅ 基础调试 | ❌ |
| 多任务并行 | ✅ 子 Agent 调度 | ✅ 多角色代理 | ❌ |
| 干扰程度 | 中（需要响应 Brainstorming 问题） | 低（配置好后可自动运行） | 高（只生成配置，需自行后续工作） |

**结论**: Superpowers 在中大型功能上体验最佳；agent-harness-kit 干扰最低但前期配置成本高；HarnessForge 仅解决"初始化"问题。

### 4.3.3 质量控制

| 维度 | Superpowers | agent-harness-kit | HarnessForge |
|------|-------------|-------------------|-------------|
| TDD 强制 | ✅ 严格（RED→GREEN→REFACTOR） | ⚠️ 可选 | ❌ |
| 代码审查 | ✅ 双阶段（规范+质量） | ✅ 10 维度专业评审 | ❌ |
| 安全审查 | ⚠️ 基础 | ✅ 专用 Security Agent | ⚠️ 仅金融蓝图有 |
| 验证强制 | ✅ 完成前强制验证 | ✅ Hook 可配置 | ❌ |
| 错误学习 | ❌ | ✅ Failures→Rules | ❌ |

**结论**: agent-harness-kit 在质量控制上最全面；Superpowers 的 TDD 和验证强制做得很好；HarnessForge 基本没有质量控制机制。

### 4.3.4 团队协作

| 维度 | Superpowers | agent-harness-kit | HarnessForge |
|------|-------------|-------------------|-------------|
| 一致性强制 | ✅ 严格流程保证 | ✅ Hook 系统保证 | ⚠️ 仅初始配置一致 |
| 多人兼容 | ✅ Git Worktree 隔离 | ⚠️ 无隔离 | ❌ |
| 评审流程 | ✅ 内置 Review 流程 | ✅ 10 维度评审 | ❌ |
| 可观测性 | ⚠️ 基础日志 | ✅ SQLite + 成本追踪 | ❌ |
| 新成员上手 | ⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

**结论**: Superpowers 在团队协作上最好——Worktree 隔离 + 标准化流程 + 评审门禁形成了完整闭环；agent-harness-kit 的 Hook 系统可补充审计能力。

### 4.3.5 成本效益

| 维度 | Superpowers | agent-harness-kit | HarnessForge |
|------|-------------|-------------------|-------------|
| 初始容量 | 小（Skill 核心仅 ~2K tokens） | 中（配置本身有成本） | 无（一次性） |
| 流程 Token 开销 | 中 | 高（评审 Agent 成本↑） | — |
| 节省的 Token | 高（减少浪费） | 高（阻止错误操作） | — |
| 时间 ROI 拐点 | 中功能（~2h）即回本 | 中~大功能 | 每次新项目立即回本 |

**成本估算（以 Claude Opus token 价格为例）**:

```
Superpowers:
  - Brainstorming ~1K tokens
  - Plan ~0.5K tokens
  - Subagent 每个 ~50-100K tokens
  - Review 每个 ~10K tokens
  → 中型功能 (~4h人工) 约 ~200K tokens → ~$X
  → 对比无 Superpowers: ~400K+ tokens (返工多)
  → 节省: ~50% tokens + 63% 人工时间

agent-harness-kit:
  - 10 维度评审 ~150K tokens/次
  - Hook 系统 ~5-10K tokens/操作
  → 额外的 Token 消耗约 20-30%
  → 但减少的错误和返工可抵消
```

## 4.4 实操中发现的模式与反模式

### ✅ 有效模式

| 模式 | 说明 | 适用工具 |
|------|------|----------|
| **Brainstorm First** | 任何代码前先做需求澄清 | Superpowers |
| **Isolated Workspaces** | 每个功能独立 Worktree | Superpowers |
| **Failures to Rules** | 错误自动转化为规则 | agent-harness-kit |
| **Context GC** | 定期清理上下文碎片 | agent-harness-kit |
| **Forge + Flow** | 先初始化再配置流程 | HarnessForge + 任意 |

### ❌ 反模式

| 反模式 | 后果 | 建议 |
|--------|------|------|
| **跳过 Brainstorming** | 后期返工率 3-5x | 不要为了快而跳过 |
| **一次性启用全部功能** | 配置负担压垮团队 | 分阶段逐步启用 |
| **Harness 替代人肉 Review** | 漏过语义理解问题 | 机器检查 + 人肉 Review |
| **所有功能都用 10 维度评审** | Token 消耗爆炸 | 按风险级别选择评审维度 |
| **只初始化不管维护** | 配置过期失效 | 定期运行 GC 和验证 |

## 4.7 核心结论（Day 1 实操阶段）

1. **Superpowers 是最推荐的起点工具**——它完整、成熟、社区活跃
2. **agent-harness-kit 是最强的补充工具**——它的安全治理和深度评审弥补了 Superpowers 的短板
3. **HarnessForge 是最高效的辅助工具**——3 秒初始化可节省大量重复配置时间
4. **不要试图一次性全量启用**——分期推进，先在 1-2 个小项目上验证效果
5. **Harness 的 ROI 在中大型功能上最显著**——小功能反而可能有流程惩罚

## 4.8 后续 12 任务量化评测结果（2026-06-11）

Day 1 实操后，补做了一轮完整的量化评测——12 个 Spring Boot 任务 × 4 组 Provider（Baseline / Superpowers / Gstack / OpenSpec），48 条数据。

### 总分排名

| Provider | 总分 | 平均分 | 满分次数 |
|----------|:---:|:---:|:---:|
| **Gstack** | **1090** | **90.8** | 2 |
| OpenSpec | 1065 | 88.8 | 2 |
| Baseline（裸Agent） | 1045 | 87.1 | 2 |
| Superpowers | 1045 | 87.1 | 2 |

### 评测对 Day 1 结论的修正

1. **Superpowers 总分 = Baseline（1045）** — Day 1 认为 Superpowers 是"最推荐的起点"，但 12 任务评测显示其严谨流程并未转化为整体得分提升。流程步骤多 ≠ 质量好。
2. **Gstack 才是最优 Harness** — 角色分工（/ceo → /engineer → /qa → /devops）比严格流程（brainstorming → plan → TDD → review）更有效。多视角覆盖同一问题 > 单人多步骤流程。
3. **Superpowers 在算法类任务上仍然最强** — 任务⑥限流中 Superpowers 是唯一满分（100），TDD 在"代码正确性可被测试明确验证"的任务上价值最大。
4. **评测设计本身的盲区** — 自动评测中 Agent 被禁止提问（AskUserQuestion 会阻塞），Superpowers 的 brainstorming 退化成了自问自答。过程评测（URL 短链接三轮对比）证实：允许用户交互后核心架构决策完全不同。
5. **所有 Harness 都怕全局重构** — 任务⑫ Flaky 测试四组全 70 分，Agent 倾向"加新代码"而非"改旧代码"，当前 Harness 都未能打破这一点。

### Token 效率

| Provider | 总 Token | 千 Token 得分 |
|----------|:---:|:---:|
| Gstack | 639K | **1.70** |
| OpenSpec | 625K | **1.70** |
| Baseline | 687K | 1.52 |
| Superpowers | 991K | 1.05 |

Superpowers 消耗了最多的 Token（+44% vs Gstack），得分与 Baseline 持平。

详细数据见 `eval/results/README.md` 和 `docs/share/Part3-数据.md`。
