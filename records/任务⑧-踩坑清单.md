## 🔴 阻塞级（不解决无法继续）

### 1. Maven 中央仓库网络超时

**场景**: 任务③
**现象**: `mvn compile` 下载依赖时 connect timeout
**根因**: Active Maven 的 `settings.xml` 无镜像配置，Maven Central 直连超时
**修复**: 在 `C:\Users\Kleaves\apache-maven-3.9.16\conf\settings.xml` 添加阿里云镜像
**教训**: 首次用 Maven 前先检查 `~/.m2/settings.xml` 的 mirror 配置

### 2. 子代理调度全部失败（DeepSeek 模型兼容性）

**场景**: 任务⑦
**现象**: Subagent-Driven Development 的三个子代理全部返回 `API Error: 400 thinking options type cannot be disabled when reasoning_effort is set`
**根因**: 当前使用的 DeepSeek 模型不支持 reasoning_effort 参数，Superpowers 的子代理调度机制与其不兼容
**修复**: 切换为 Inline Execution（主会话内直接执行）
**教训**: Superpowers 的子代理功能依赖 Claude 原生 API 参数。非 Claude 模型使用时需提前验证兼容性，建议备好 Inline Execution 回退方案

## 🟡 阻碍级（能绕过但浪费了时间）

### 3. 同一会话实验交叉污染

**场景**: 任务④
**现象**: Superpowers 和裸 Agent 在同一个会话里先后跑，产出代码几乎一样
**根因**: Agent 会读取之前的对话上下文（文件、讨论、选择），第二个实验不再是独立变量
**修复**: 分开两个独立会话运行，prompt 差异最小化
**教训**: A/B 实验严格隔离——新会话 + 干净的 workspace 副本

### 4. agent-harness-kit init 权限编译失败

**场景**: 任务⑤
**现象**: `npx agent-harness-kit init --yes` 报 `permissions compile failed during renderAll`
**根因**: kit 检测到 generic/generic 项目类型时，默认 permissions 模板中包含了很多 TS/Python 项目的期望路径（如 `.harness/scripts/*.mjs`），这些在 Java 项目中不存在
**影响**: CLI 报错退出，但实际上大部分文件（`.claude/`、`.harness/`、`CLAUDE.md`）已生成完毕，只是编译权限 JSON 时中断
**教训**: kit 对非 TS/Python 项目的 init 不稳定——文件实际已生成可用，权限编译失败可以忽略继续用

### 5. harnessforge inspect 框架检测全面漏检

**场景**: 任务⑥
**现象**: 检测 Spring Boot + Maven 项目，输出 `frameworks: 无`、`package mgrs: 无`、`build: 无`
**根因**: v0.2.2 的 inspect 基于简单的文件存在检测（如 `package.json`、`go.mod`），不认识 `pom.xml` 作为构建系统标志
**教训**: inspect 结果不可盲信，只能参考语言检测。框架/构建工具需要手动补全 `profile.yaml`

### 6. kit init 语言参数不支持中文

**场景**: 任务⑤
**现象**: `--lang zh` 报错 `Unsupported humanLanguage "zh". Supported: en, vi`
**根因**: v0.22.3 的 CLAUDE.md 模板只支持英文和越南文
**教训**: 生成的 CLAUDE.md 是英文的，需手动翻译或直接使用

### 7. kit init 交互式模式在非 TTY 环境被中断

**场景**: 任务⑤
**现象**: `npx agent-harness-kit init` 弹交互式选择后 `aborted by user`
**根因**: 没传 `--yes`，工具进入交互式 Q&A 但当前环境不支持
**修复**: 加上 `--yes` 接受所有默认值
**教训**: CLI 工具初始化总是先 `--help` 看有没有跳过交互的 flag

## 🟢 轻度级（不影响进度但值得记录）

### 8. @Digits 注解与 Double 类型不兼容

**场景**: 任务③
**现象**: `@Digits(integer=10, fraction=2)` 加在 `Double price` 上，校验时抛内部异常绕过 GlobalExceptionHandler，返回 Spring 默认 400 页面而非结构化 JSON
**根因**: Jakarta Bean Validation 的 `@Digits` 只支持 `BigDecimal`、`BigInteger`、`String` 和整数包装类型，不支持 `Double`
**修复**: 自定义 `@PriceFormat` 注解 + `PriceFormatValidator`，用 `BigDecimal.valueOf(value).scale() <= 2` 做小数位检查
**教训**: Jakarta 校验注解不是对 Java 基础类型都友好的——`@Digits` 写入 plan 前先确认字段类型。建议用 `BigDecimal` 存价格

### 9. pip 命令在 bash 中找不到

**场景**: 任务⑥
**现象**: `pip install harnessforge` → `command not found`
**根因**: Windows Python 的 `pip` 不在 bash PATH 中
**修复**: 用 `python -m pip install harnessforge` 替代
**教训**: Windows 环境下用 `python -m pip` 比直接用 `pip` 更可靠

### 10. 裸 Agent 未经需求澄清擅自扩大范围

**场景**: 任务④
**现象**: 一句话 "加校验" → 裸 Agent 不仅给请求体加了 `@Valid`，还给 `@PathVariable Long id` 加了 `@Positive`、`@RequestParam String author` 加了 `@NotBlank`
**根因**: 无 brainstorming 做边界确认，Agent 按自己的"合理"判断扩展
**教训**: prompt 中的边界约束很重要——要么明确说"只做 XXX"，要么走 brainstorming 流程确认

### 11. size 边界值 clamp 逻辑容易写反

**场景**: 任务⑦
**现象**: 首版 `Math.max(1, Math.min(100, size))` 将 `size=0` 截断为 1 而非默认值 20
**根因**: 两层 clamp 的嵌套顺序：应该先判断 <1 回退默认值，再截断上限，而非 `max(1, min(100, x))` 这种丢失语义的写法
**修复**: `size < 1 ? DEFAULT : Math.min(MAX, size)`
**教训**: 边界值处理不要用链式 clamp 一把梭——三个分支（小于下限、正常、大于上限）各自行为不同

## 给后续 Day 2-4 的建议

1. **子代理不可用时直接走 Inline Execution**，不浪费时间重试
2. **A/B 对比实验严格用独立会话 + 干净工作区副本**
3. **kit 和 Forge 的 init 用非交互模式**（`--yes` 或 `--no-llm`）
4. **价格字段统一用 BigDecimal**，避免 @Digits 兼容问题
5. **prompt 中加边界约束**：明确说不改什么，比只说改什么更重要
6. **边界值处理先分三支再 clamp**，不要链式嵌套 Math.max/min
